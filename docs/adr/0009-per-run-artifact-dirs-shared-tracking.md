# Per-run artifact dirs with shared tracking stores

Run output is split into two kinds of location under a single `<output_base>` because per-run artifacts and experiment tracking have opposite directory needs. Heavy artifacts (checkpoint, best, configs, logs, inference, MLflow `run_context_dir`) go in a per-run isolated dir `<output_base>/runs/<run_id>` so consecutive runs never clobber each other. Experiment tracking stays shared and run-independent: `<output_base>/mlflow` is one MLflow store that keys each run's metrics and artifacts by MLflow's own `run_id`, and `<output_base>/tensorboard` is one TensorBoard logdir with each run as a subdir, so a single UI compares all runs.

The rule: tracking stores anchor to `<output_base>`; heavy artifacts anchor to the per-run dir. Previously everything derived from a single `output_dir`, so a fixed dir made MLflow work (shared store) only by clobbering checkpoints. The factory already separates MLflow `tracking_dir` (the store) from `run_context_dir` (the run's working dir), so this is a wiring change, not a redesign — MLflow artifacts and TensorBoard comparison both keep working. The run-directory tree is created in one place (`prepare_run_layout`) rather than split between the CLI and downstream callbacks, and `output_dir` collapses to a single owner (CLI overrides `engine.execution`).
