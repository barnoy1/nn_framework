# Checkpoint load strictness is gated by flow

Weight loading uses two policies chosen by flow/intent, not by mechanism. The train flow allows a partial load (legitimate warm-start, e.g. introducing new classes from vanilla DETR weights) but emits a loud warning summarizing loaded/skipped/missing tensors — never silent. The eval and inference flows require a complete load and fail fast on any missing or shape-mismatched core weights, because a half-loaded model produces silently-wrong metrics and there is no training step to recover a random head; an explicit `--allow-partial` opt-out exists for debugging. A head class-count mismatch during eval is always a hard error (almost always a wrong checkpoint/config pairing). This replaces the previous behavior where `validate_checkpoint_class_compatibility` was a no-op stub and `safe_load_state_dict` silently skipped keys in every flow.
