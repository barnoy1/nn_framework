# Split experiment.yaml into engine and adapter namespaces

The experiment config is reorganized under two top-level namespaces so the framework/adapter boundary is visible at a glance: `adapter` holds everything the adapter/model owns (model definition, losses), and `engine` holds everything the framework owns (`train` training math incl. explicit optimizer/scheduler blocks, `data`, and `execution` — the environment/flows/IO section, renamed from the old top-level `runtime` so that "runtime" can mean only the live model-side execution graph). Each setting has exactly one owner; the previously duplicated `epochs`/`batch_size`/`num_workers`/`seed` keys are removed from `runtime` so the training loop and the scheduler read the same `engine.train` values, eliminating split-source-of-truth bugs (e.g. cosine `T_max` disagreeing with loop epochs). Optimizer and scheduler become explicit, fail-fast-typed blocks under `engine.train`.
